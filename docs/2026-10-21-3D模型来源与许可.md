## 一、结论

| 项 | 决定 |
|---|---|
| 项目代码许可 | **MIT 或 Apache-2.0**（用户 2026-10-21 选定：会开源） |
| 3D 模型 | **Z-Anatomy**，`Z-Anatomy/Models-of-human-anatomy` |
| 模型的许可 | **CC BY-SA 4.0**（随模型原样遵守，不试图绕过） |
| 分层 | **代码 MIT / 3D 资产 CC BY-SA**，两者在仓库里分开放、分别声明 |
| BodyParts3D | 弃用（许可证合格，但肌肉只有区域级，做不了逐块高亮） |

## 二、为什么优先 CC BY 而不是 CC BY-SA

用户要开源成 MIT/Apache。ShareAlike 会粘住 3D 资产：用了 CC BY-SA 的模型，
那个模型（以及我们对它的修改）必须继续 CC BY-SA。

**严格说这不必然传染整个应用**——一个运行时加载的独立资产文件更接近「汇集」而非
「演绎」——但这是个有争议的边界，而争议本身就是成本：想给项目换个许可时要先论证
「我们没被传染」。

CC BY 4.0 只有一条义务：署名。所以只要候选模型够用，就选 CC BY。

## 三、BodyParts3D 为什么不可用（实测，不是猜）

许可没问题。[官方许可页](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)
（2025/02/27 更新）写明 **CC BY 4.0**，允许自由创建并分发衍生作品，只要署名。

**问题是它的模型覆盖不到「逐块肌肉」。** 我下了两份官方部件清单逐一核对：

| 清单 | 条目数 | 含 `muscle` 的 | 具体内容 |
|---|---|---|---|
| `partof_parts_list_e.txt`（62 MB 包） | 1,368 | **9** | 全是心脏乳头肌与肠壁肌层，**没有骨骼肌** |
| `isa_parts_list_e.txt`（136 MB 包） | 2,905 | 93 | 绝大多数是**区域级**：`muscle of thorax`、`muscle of abdomen`、`muscle of posterior compartment of thigh` |

按我们 17 个肌群逐一查 ISA 清单的结果：

| 肌群 | 命中 |
|---|---|
| 胸部（pectoralis） | 13 条，但多数是 `pectoralis minor` 与 `deltoid branch of ... artery`（血管） |
| 三角肌（deltoid） | 同上，**没有独立的三角肌网格** |
| 肱二头（biceps） | 13（`short head of biceps brachii` 等） |
| 肱三头（triceps） | 9 |
| 斜方肌（trapezius） | 10（`zone of trapezius`） |
| 臀（gluteus） | 9（`gluteus maximus` 有） |
| 小腿（gastrocnemius / soleus） | 7 / 3 |
| **背阔肌（latissimus）** | **0** |
| **腹直肌（rectus abdominis）** | **0** |
| **腘绳肌（hamstring）** | **0** |

结论：BodyParts3D 是**器官级的解剖数据集**（动脉、静脉、骨、脏器），
它的「肌肉」是区域团块。拿它做「点一下背阔肌高亮背阔肌」只能高亮
`muscle of back` 那种团块（而且那个键本身是 0 条，只能退到 `muscle of trunk`），
**在解剖上是错的，等于骗用户**。

皮肤倒是有（`skin`，2 条），所以「半透明皮肤」这一层它给得了。

## 四、下一个候选的评估要点

选新模型时按这个顺序核：

1. **许可**：CC BY / CC0 优先；CC BY-SA 只在没有 CC BY 替代时考虑，并明确记录
   「3D 资产是 CC BY-SA、应用代码是 MIT」这个分层
2. **逐块肌肉**：至少要能单独取出我们 17 个肌群对应的网格。**先看它的部件清单，
   不要先下 100 MB 的包**——这一轮的教训就是「许可合格 ≠ 覆盖合格」
3. **面数**：目标是把整包压到 **10 MB 以内的 glb**。参考：BodyParts3D 的 99% 简化包
   仍有 62 MB（zip）/ 136 MB（zip）
4. **有没有皮肤层**：参考图那种半透明效果需要一层外壳
5. **格式**：优先 `.glb` / `.gltf`；`.obj` 要用 trimesh 转；`.blend` 需要 Blender

## 六、Z-Anatomy 的实施路径（2026-10-21 勘查结果）

### 现状：仓库里没有能直接用的网格

Z-Anatomy/Models-of-human-anatomy 的根目录只有 9 个文件，
Z-Anatomy.zip（86.7 MB）装的是 **Blender 工程**。
全仓 **0 个** .glb / .gltf / .fbx / .obj —— 没有任何预导出网格。

所以必须自己跑一条 lend -> glb 的管线。

### 管线

`
1. winget install BlenderFoundation.Blender        # 本机目前没有 Blender
2. 解压 Z-Anatomy.zip，得到 .blend
3. blender --background <file>.blend --python export.py
     - 按肌群选中对象（Z-Anatomy 用 collection / 命名组织，需先探明结构）
     - 每块肌群 Decimate 到几千面
     - 按 17 个肌群 join / 或保留为独立对象并命名
     - 导出 .glb（embedded）
4. 把 glb 放进 frontend/src/assets/anatomy/，用 Three.js 加载
5. 点选：raycast 命中对象的 name -> muscleGroupId
`

### 这条路的三个真实难点（不是「多写几行代码」那种）

1. **本机没有 Blender，也没有 trimesh**，而 .blend 没法用纯 Python 读。
   Blender 是 ~300 MB 的安装，且导出必须 headless 脚本化。
2. **Z-Anatomy 的对象组织方式需要先探明**才有办法「按肌群取」。
   它的肌肉是按 collection 还是按命名前缀组织的，只有打开工程才知道。
3. **我看不到渲染结果。** 这是最要紧的一条——我可以断言「导出了 17 个对象、
   每个 3-8 千面、包围盒在这个范围」，但**没法判断它看起来对不对**
   （朝向、比例、肤色、皮肤透明度、选中高亮是否明显）。
   3D 资产是那种「结构全对但就是难看」的东西，纯靠数字验不出来。

### 因此这件事的推进方式

不是「我一口气做完给你」，而是：

- 我负责：安装与脚本化导出、对象结构探明、glb 体积与面数控制、Three.js 接入、
  17 个肌群到对象名的映射、点选逻辑与测试
- 你负责：每次我导出一个版本，你打开看一眼，告诉我「朝向反了 / 太暗 / 皮肤太透 /
  选中看不出来」这类只有眼睛能发现的问题

**如果不同意这种来回，那就应该重新考虑第 4 节里「用现有 2D 区域自己造 3D」
那个选项**——它不好看，但它不需要任何外部资产，也不需要视觉迭代。
