## 一、项目定位

一个**只服务自己一个人**的健身记录客户端。项目名 `change`（改变）。

针对的痛点很明确：市面上的健身 App 都是商业订阅制，功能被订阅墙切碎、有广告、导出受限、食物库偏西式包装食品、计划是静态模板而非按个人历史递进。**这些槽点几乎都源于多租户订阅制，单用户自建可以全部规避。**

## 二、四个核心决定（已封板）

### 决定 1 · 产品形态 = 桌面客户端

- 不做网页，不做手机 App，**做成有独立窗口的桌面客户端**（双击运行，无地址栏、无标签页）。
- 参考物：用户提供的「B站工具箱」——Tauri 2 外壳 + Vue 3 前端 + 独立业务后台。
- **映射关系：把其中的 Python 后台换成 Java 后台，其余层照搬。**

### 决定 2 · 「打卡」= 训练日志（不是出勤打勾）

- 数据结构：**训练 → 动作 → 组**（`Session → Exercise → Set`）。
- 关键设计要求：**目标值与实际值同表并存**，用 `slot_entry` 反指计划，避免每次训练复制一遍动作结构。
- 组类型用枚举（normal / warmup / dropset / myo / partial / forced / tut / iso / jump），比「第几组」表达力强。
- 为什么不做最轻的出勤打卡：记录不了重量次数，看不到自己有没有变强；三个月后只有一堆日期，没有信息。
- 为什么不做最重的计划驱动：它是本决定之上再加一层，随时能加，不用返工。

### 决定 3 · 饮食记录 = 条目化 + 食物库

- 数据结构：**餐 → 条目 → 食物 + 份量**（`Meal → MealItem → Food + amount`）。
- **硬性约束：营养值一律按每 100 克存，份量单独存。**
  热量 = `amount × gram / 100 × 每百克营养值`。**条目里绝不留绝对热量**，否则换算单位后立刻算错。
- 单位换算靠一张「每食物克重表」（1 碗 = 多少克、1 勺 = 多少克）。
- 拍照识别只是「加一条」的快捷入口，不是独立功能。
- **用户明确定位：不需要太精准，大致热量即可。精度不是目标，可修正是。**

### 决定 4 · 智能体 = 可读也能写（工具调用）

- 它能看到训练、饮食、体重数据，回答「我这周练了几次」「蛋白够不够」。
- **它也能改数据**：用户说「中午吃了两个包子一碗粥」→ 它直接建条目；说「那个鸡腿其实是炸的」→ 改条目并重算热量。**说话就是录入。**
- 技术上就是 **tool calling**——这正是用户「Java + agent」学习方向的核心。
- **必须配套的安全线**：只允许「新增」和「修改」，**不允许删除**；每次改动留一条操作记录，可一键回退。

## 三、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面外壳 | **Tauri 2 + Rust** | 用户选定；安装包约 10 MB；与参考项目同构 |
| 界面 | **Vue 3 + TypeScript + Vite + Pinia + Vue Router** | 与参考项目同构，生态成熟 |
| 业务后台 | **JDK 25 + Spring Boot 3.x + Maven** | 用户学习方向；Maven 3.9.4 已就绪 |
| 智能体 | **LangChain4j + DeepSeek（OpenAI 兼容端点）** | 纯 Java 库；tool calling / 结构化输出 / SSE 流式齐全 |
| 数据库 | **SQLite 单文件** | 免运维；备份 = 复制一个文件 |
| 图片存储 | **本地文件系统** | 隐私优先；库里只存相对路径 + 哈希 |
| 前后端通信 | **本地 HTTP，127.0.0.1 随机端口** | 比 stdio JSON 管道简单；调试可直接用浏览器看接口 |
| Excel 导出 | **Apache POI** | Java 版，对应参考项目的 openpyxl |

**明确排除的选项**（记录理由，避免以后重复讨论）：

- **Semantic Kernel Java** —— Java 分支已废弃，微软主线转 Agent Framework（仅 .NET / Python / Go）。
- **Spring Boot 4 / Spring AI 2.x** —— 建在 Spring Framework 7 上，与 Boot 3.x 线分叉，暂不采用。
- **Google ADK for Java** —— 偏 Gemini、RAG 弱，留作第二阶段学习目标。
- **Electron** —— 零工具链但安装包 150 MB；用户明确选了 Tauri。
- **JavaFX 纯 Java 客户端** —— 界面工作量大数倍，会把时间从「Java + agent」挪到「手写界面」。
- **微信小程序** —— 注册审核流程长，自用场景没必要。

**为了让工具链在任意 shell 都能用（绕开 DSH 环境陈旧的问题），额外建了两个目录联接**（`mklink /J` 的 PowerShell 等价物，不需要管理员权限；数据实际仍存在 E 盘，C 盘只多两个链接项）：

| 联接位置 | 指向 |
|---|---|
| `C:\Users\alpaca\.rustup` | `E:\devtools\rustup` |
| `C:\Users\alpaca\.cargo` | `E:\devtools\cargo` |

**其它已配置的工具目录**：

| 配置 | 值 | 位置 |
|---|---|---|
| cargo 镜像 | crates.io → 中科大 sparse 索引 | `E:\devtools\cargo\config.toml` |
| npm 缓存 | — | `E:\devtools\npm-cache` |
| pnpm store | — | `E:\devtools\pnpm-store` |
| Maven 本地仓库 | 尚未配置（建项目时设） | `E:\devtools\m2` |

**已完成端到端验证**：`cargo new` → `cargo build` → 运行产物，全部通过，且**不需要手工注入 VS 环境变量**（rustc 能自动探测到自定义路径下的 MSVC 工具集 14.44.35207）。

### Tauri 全链路冒烟测试 ✅ 通过

今晚跑了一次真实的 Tauri 工程编译，结论是**这条链没有阻塞**：

| 步骤 | 结果 |
|---|---|
| `create-tauri-app` 生成工程（vanilla-ts 模板） | ✅ |
| `npm install`（走 npmmirror） | ✅ 20 个包 / 13 秒 |
| `cargo build`（Tauri 2.12.3，约 400 个 crate，走中科大镜像） | ✅ **1.9 分钟** |
| 产出产物 | ✅ `change-smoke.exe`，**12 MB** |

两点值得记住：

- **12 MB** 这个数字验证了选 Tauri 的核心收益——同样的界面用 Electron 要 150 MB 起。
- 全局 cargo 包缓存已积累 **321 MB / 10881 个文件**，明天真实项目的首次编译会直接复用，不用再等一遍网络。

冒烟工程留在 `E:\devtools\cache\tauri-smoke\change-smoke`（已删编译产物），可当作脚手架参考。

**另一个坑**：`npx` 拉包时曾报 `EE certificate key too weak`（连 registry.npmjs.org 时证书被中间设备替换）。**已把 npm 与 pnpm 的源都切到 `https://registry.npmmirror.com`**，问题消失。

**本机原有、无需安装**：JDK 25.0.2（`C:\Users\alpaca\.jdks\openjdk-25.0.2`）、Maven 3.9.4（`E:\maven`）、Node 24.15.0、npm 11.12.1、pnpm 11.21.0、Python 3.14.6、WebView2 运行时 155.0.4283.45、winget 1.29.380。

**踩过的坑（供以后参考）**：

- `static.rust-lang.org` 国内仅 ~19–27 KB/s，不可用。
- 清华镜像的 rustup-init 正确路径是 `/rustup/rustup/dist/...`，不是 `/rustup/dist/...`（后者 404）。
- **PowerShell 的 `Invoke-WebRequest` 会 0.2 秒返回 0 字节的空文件**；改用 `curl.exe` 才正常。
- **可用镜像**：USTC `https://mirrors.ustc.edu.cn/rust-static`（实测 3.4 MB/s，最快）、清华 `https://mirrors.tuna.tsinghua.edu.cn/rustup`（1.9 MB/s）。
- VS C++ 生成工具有约 2 GB 临时下载强制走 C 盘（Windows 安装器行为），装完会自动清理。
- **DSH 进程的环境变量是陈旧的**：新写入的用户级 `RUSTUP_HOME` / `CARGO_HOME` 传不进后续命令，导致 `rustc` 报「no default toolchain」。**改用目录联接（junction）绕过**——把 `C:\Users\alpaca\.rustup` 和 `.cargo` 联接指向 `E:\devtools\` 下的真实目录，于是不带任何环境变量也能工作。注意：rustup 代理会自己创建一个**空**的 `.rustup` 目录，必须先删掉再建联接，否则静默失效。
- **cargo 默认从 crates.io 拉包，国内极慢**，必须配镜像。已写入 `E:\devtools\cargo\config.toml`（经联接等价于 `~\.cargo\config.toml`）：crates-io 替换为中科大 sparse 索引。

## 五、风险清单

| 风险 | 程度 | 应对 |
|---|---|---|
| **JDK 25 与 Spring Boot 3.x 的版本搭配未验证** | **高** | 动工第一件事就是跑最小骨架验证掉它 |
| Java 生态没有成熟可抄的健身项目 | 中 | 数据模型照 wger 思路用 Java 重写；前期多花时间，但这正是学习价值 |
| LangChain4j 迭代极快（1.11 → 1.22 仅两个月） | 中 | 锁版本 + BOM 统一管理；以英文文档和 release notes 为准 |
| 拍照估热量不够准（同图实测差 300+ 千卡） | 中 | 定位为估算 + 一句话修正，不做精确测量 |
| 照片隐私（食物照、身材照出网） | 中 | 模型接口单独成一格，可一键关闭、可换本地模型 |
| Tauri 首次编译慢、依赖 MSVC 工具链 | **已消除** | 已实测全链路通过：Tauri 2.12.3 编译 1.9 分钟，产出 12 MB exe |
| 自用 API 成本 | 低 | DeepSeek 降价后自用月成本 < 1 元 |
