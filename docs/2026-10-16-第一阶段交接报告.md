## 四、这一路抓到的最有价值的东西

十一个任务、每一轮都做了「实施 → 规格审查 → 质量审查」。**每个任务都发现了我计划本身的缺陷**，累计三十余处。挑五个最值得记的：

| 发现 | 失效形态 |
|---|---|
| 数据目录从不被创建 → 干净环境必 `SQLITE_CANTOPEN` | 响亮失败（好） |
| `server.port: 0` 未配 `server.address` → 后端监听所有网卡，而它**没有鉴权** | 安全缺陷 |
| SQLite 默认 `foreign_keys = 0` → 迁移里所有 `ON DELETE CASCADE` **全是装饰** | 静默 |
| 日期列无形状约束 → 写进时间戳会让等值查询**静默返回 0 行**、索引白建 | 静默 |
| xerial 默认把 `LocalDateTime` 写成**纪元毫秒** → `started_at` 存成 `'1791977415000'` | 静默 |
| `round2(NaN) = 0.0` → 一餐可以安静地显示 **0 kcal** | 静默 |
| `classify(NaN) = IN_RANGE` → **达标绿**，最危险的错答案 | 静默 |
| `undo` 的 `rowid` 能通过标识符正则 → 静默**改写目标行主键** | 静默 |
| 熔断器 `isBroken()` 无条件清零计数 → **永不触发**（死代码） | 失效的保护 |
| `after_json` 的键从不校验（而 `before_json` 逐列校验） | 收口只做一半 |

**共同形态**：这些都不报错。最终审查把它们反推成七个可机械检查的形态，扫了一遍最终代码：

| 形态 | 判定 |
|---|---|
| A 静默失效 | 已处理（`after` 键校验是最后一处） |
| **B 收口只做一半** | **本轮修掉**（`after` vs `before`）——这是本项目最容易复发的模式 |
| C 恒真/无判别力断言 | 已处理（逐条自查 + 变异测试） |
| D 写了 ≠ 生效 | 部分处理（`RedisTimeoutConfigTest` 是唯一一类哨兵） |
| E 死代码冒充保障 | 已处理（计划里的坏熔断器已同步） |
| F 无界输入的溢出 | 本轮修掉（`sum` 溢出守卫） |
| G 共享可变状态 | 本轮修掉（熔断计数器改原子类型） |

## 六、已知的、有意留下的缺口

这些**不是遗漏**，是明确记录在案、等后续任务处理的：

### 1. 计划 fence 与磁盘「逐字一致」靠人工跑脚本，没有守卫

最终审查发现 13 处「规格落后于代码」（其中 1 处是真的：Task 11 Step 4 计划里那份熔断器是坏的）。已全部同步，但**没有机械化守卫**——下次改了代码忘了改计划，不会有任何东西报警。

**建议**：加一条测试，把计划里带「已与磁盘逐字一致」标记的 fence 与磁盘比对。我没有擅自加——它需要先约定标记格式，且会让计划文本成为构建输入，是个设计决定。

### 2. 并发安全没有判别性测试

熔断计数器已改成原子类型，但**仓库里没有任何测试能判别它**。实测根因：x86 上 `int++` 是**一条读-改-写指令**，没有窗口；且阈值只有 3，所以「N 线程各失败一次然后断言熔断」这个形状与丢失更新**结构性地不相干**。

那条测试被如实标注为「**回归守卫，不是判别器**」，并写明「不要因为它现在是绿的，就以为并发安全有测试守着」。

### 3. 还有 7 个枚举列没有 Java 侧白名单

9 处 `TEXT + CHECK (x IN (...))` 里只有 2 处（`exercise_muscle.role`、`workout_set.set_type`）有白名单 + 防漂移测试。其余 7 处（`food.source` / `photo.kind` / `meal.slot` / `meal_item.origin` / `chat_message.role` / `change_log.origin` / `change_log.action`）只在 DDL 里拦。

后果不是「数据会脏」（DB 会拒），而是**报错点离出错点很远**：导入器把 `"Breakfast"` 写进 `meal.slot`，失败形式是一句 `CHECK constraint failed`。已记进计划待办。

### 4. 7 张白名单表既没有实体也没有 `validate` 兜底

`ddl-auto: validate` 只校验 JPA 实体，而全项目只有 4 个实体。`ChangeLogService` 用手写 SQL 操作 `food` / `meal` 等 7 张表——**字符串列名是它们唯一的「契约」**。

缓解项：`MigrationTest` 把 V1–V4 的 checksum 钉死了，schema 改不动。

### 5. 测试共用磁盘数据库，中断会留残留

所有 `@SpringBootTest` 共用 `target/data/change.db`，**跨运行持久**。`@Transactional` 的测试自我回滚，但**中途终止**（Ctrl-C、超时）会让未提交的行落到磁盘——而 `ux_exercise_name_en` 是唯一索引，下次运行可能撞 `UNIQUE` 冲突。

`ChangeLogServiceUndoTransactionTest` 已为**自己**开了独立库并做了清理，但主库没有。**临时规避**：`mvn clean test`（`clean` 会删掉 `target/`）。

### 6. `_review/` 里的原始日志不在版本库里

那批验证脚本因硬编码了本机路径被移出版本库（理由充分：它们不是可复跑验证而是单机产物）。代价是那些 `*.log`（每轮审查的原始输出）现在**只存在于本机磁盘**——一次误删或换机器就永久消失。多数关键结论已提炼进计划，但原始证据不可追溯。

## 七、分发相关的决定

| 项 | 决定 | 理由 |
|---|---|---|
| 数据目录 | `%APPDATA%\changE`，可用 `CHANGE_DATA_DIR` 覆写 | 双击启动时工作目录不确定，相对路径会落到随机位置 |
| `change.redis.enabled` | **默认 `false`**，可用 `CHANGE_REDIS_ENABLED` 覆写 | 朋友的机器上没有 Redis；开着会让首次启动白等约 0.5 秒（实测） |
| Redis 主机 | 标注为「**示例值**——作者内网的一台虚拟机」 | 默认关闭后不再泄漏到健康端点 |
| 后端监听 | `server.address: 127.0.0.1` | 无鉴权的后端不该监听所有网卡 |
| 构建体积 | fat jar **79.1 MB**，精简 JRE **47.4 MB**，完整安装包约 **138 MB** | 实测值 |

### ⚠️ 给加写接口的任务的安全约定（**必须在第一个写接口之前落地**）

已写进计划 Task 10 末尾，摘要：

1. **必须校验 `Host` 头**（只接受 `127.0.0.1:<端口>` / `localhost:<端口>`）——**反 DNS rebinding 的唯一最小措施**。实测后端原本接受任意 `Host`。
2. **必须强制要求一个自定义请求头**——它会强制触发 CORS 预检，而预检失败时浏览器**根本不发真实请求**。
3. **不要把 Origin 校验当替代品**——DNS rebinding 下攻击页面与目标同源，`Origin` 合法且不触发预检。
4. **别指望随机端口当安全措施**；令牌不落盘、不进日志、**不进前端 JS**。

## 八、下一步

计划 1 完成后进入**计划 2：动作库导入与肌群映射**。它需要本阶段产出的 `exercise` / `muscle_group` / `exercise_muscle` 三张表与 `ExerciseRepo`。

**开工前必须先定的四件事**（计划里已给依据）：

1. **`exercise_muscle` 的审计方案** —— 计划 2 正是**批量写这张表**的那一份，而当前 `undo` 回放不了 join 行（实测：撤销一个 `exercise` 的 insert 会**级联删掉**映射行，而快照里没有映射 → 「撤销后再重做」**静默丢掉肌群标注**）。不先给出「撤销一次导入」的方案，导入 876 个动作就会产生 876 条**撤销不完整**的日志行。
2. **`muscle_group` 的种子数据与 `region_ids` 的取值口径** —— `body_part` 与 `region_ids` 是逗号分隔的多值列，但**没有任何地方定义一份区域 id 的枚举**。计划 6 的 2D 人体图要靠它，计划 2 是唯一定义它的时机。
3. **876 个动作的来源与字段映射表** —— 总览只说「876 个动作入库、带中文名」，没说从哪个数据集、缺中文名怎么办、`is_compound` 怎么判定。
4. **`ExerciseRepo` 的两个查询方法补验证** —— 它们**零测试覆盖**，而计划 2 会立刻用到（含 `IgnoreCase` + `Containing` 的中英混合搜索）。不先补，第一次真实使用就是它的第一次执行。

**另外四条已经写好的约束**（计划里逐字可用）：

- `exercise.name_en` 的**唯一索引**把「动作身份」压在英文名书写规范上——导入器必须适配它，不是它适配导入器
- `source_id` 用**命名空间前缀**（形如 `free-exercise-db:barbell-bench-press`）；手工录入必须写 `NULL`，**空串不等于 NULL**（写 `''` 第二次导入就撞唯一索引整批回滚）
- `muscle_group.weekly_sets_min/max` **必须成对保存**（`classify` 对「半个区间」返回 `NOT_CONFIGURED`）
- `food.name_zh` **故意不唯一**，导入器有义务在报告里列出疑似重复项
