## 三、⚠️ 工具陷阱（本轮新增，每条都实际踩过）

### 1. `shell_command` 跑的是 **cmd.exe**，不是 PowerShell

用 `$env:X = …` 或 `& '...'` 会报「文件名、目录名或卷标语法不正确」。
**PowerShell 语法一律用 `powershell` 工具。**

### 2. **覆盖 `$env:Path` 而不是 prepend，会让一批无关测试变红**

本轮实际发生：`$env:Path = "E:\npm-global;C:\Windows\System32;C:\Windows"` 丢掉了一部分路径之后——

- `cargo test` 里两条**既有的**、与本轮改动无关的测试红了（`a_child_that_never_prints_the_protocol_line_times_out` / `shutdown_actually_kills_the_child`）：它们用 `cmd /c ping` 当长命子进程，而 `ping` 找不到，子进程立刻以 1 退出。
- `pnpm` 报 `无法将"node.exe"项识别为 …`。

**症状看起来像代码坏了，实际是环境坏了。** 永远这样写：`$env:Path = "<要加的目录>;$env:Path"`。

### 3. `mvn` 必须在 `backend/` 里跑

在仓库根跑会找不到 pom，`package exit=1`（本轮踩过一次，且当时误以为是编译错误）。

### 4. `mvn clean test` 删掉 jar，**包括已打好的**

跑完测试再 `java -jar` / `pnpm tauri dev` 会报 `Unable to access jarfile`。顺序永远是
`clean test` → `-DskipTests package` → `java -jar`。本轮因此重打过三次包。

### 5. **MockMvc 不跑 `/error` 页**

给 `ResponseStatusException` 加 `@RestControllerAdvice` 之后，`TrainingControllerTest` 里那条
「`timestamp`/`path` 不该存在」的断言在 MockMvc 里是**恒真**的——没有 handler 时正文干脆是空的，
而不是 Spring 的默认错误体。**真正给那两条牙齿的是 Rust 侧打真实服务器的 e2e**
（`end_to_end_proxy_reads_and_reports_statuses_from_the_real_backend` 里的 `!body.contains("timestamp")`）。
写测试时要分清「这条断言在 MockMvc 里能不能失败」。

### 6. **裸 `new ObjectMapper()` 本来就严格**

`FAIL_ON_UNKNOWN_PROPERTIES` 在裸 mapper 上默认是 `true`；**被 Spring Boot 关掉的是容器里那个**。
所以 `new ObjectMapper().enable(FAIL_ON_UNKNOWN_PROPERTIES)` 这一行**是冗余的**——变异删掉它，15 条测试全绿。
（本轮已在代码注释里如实标注。留着它是为了把要求写在它该在的地方，以及将来有人改成注入 Spring 的 mapper 时还能拦住。）

### 7. **独立库文件里也不是空的**

`NutritionControllerTest` 用独立 DB 文件，而每个新上下文启动时都会跑动作库导入与食物 seed——所以那张
`change_log` 里有 **3463 条 `origin='import'`**、`food` 里有 35 条。
断言「整张 change_log 为空」是错的；清理与断言都要**收口到本域的 target_table / origin / target_id**。

### 8. 测试数据会与随包 seed 撞车

把英文名写成 `Chicken Breast`，而 seed 里有三条英文名含 `chicken` 的食物（cooked chicken breast /
chicken thigh / kung pao chicken）——`containsExactly` 因此多出三条而变红。
**测试数据与随包数据撞车时，坏的是测试而不是代码。** 用撞不上的记号。

### 9. Vue 里 `<option :value="null">` 在 DOM 里的 value **不是空串**

按 `''` 去 `setValue` 会一个 option 都不选中 → `v-model` 拿到 `undefined` → 整行渲染不出来
（本轮就这么让一条测试炸了）。**按实际 option 的 `value` 去选**，并额外断言「请求里那一项是 `null`」。

### 10. `InvokeArgs` 断言到自己的类型要过一道 `unknown`

`c[1] as Req` 会被 `vue-tsc` 拒（TS2352），要写 `c[1] as unknown as Req`。
`pnpm test` 不会报这个——只有 `pnpm build` 会。

### 11. 继承自上一轮、仍然有效

- **绝不用 PowerShell 做文本往返**（`Get-Content`/`Set-Content` 默认 ANSI，会毁 UTF-8）。
- PowerShell 的 `*>` 重定向写的是 UTF-16LE；用 Python 读日志要按 BOM 判断编码。
- **绝不用 `java -cp target/classes` 探行为**（会读到陈旧 class）。
- 变异测试的还原用字节级备份或精确的第二次编辑，不要 `git checkout --`。
- 中文提交信息用 `git commit -F <文件>`（文件经 Python/write_file 写 UTF-8/LF）。
- `write_file` / `edit_file` 改**已存在**的文件前，该文件必须在本会话里被读过。

## 五、接口清单（前端要用）

基地址 `http://127.0.0.1:<CHANGE_PORT>`。前端**一律经 `invoke('api_request', {method, path, body})`**，不碰 `fetch`。
错误正文统一是 `{error}`（400 校验失败 / 404 找不到都由 `ApiErrors` 产生）；传输失败是 invoke 的 reject。

### 训练

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| POST | `/api/sessions` | `SessionInput` | `{sessionId, exercises, sets}`；不合法 → 400 |
| GET | `/api/sessions/recent` | — | 最近 5 次 `[{id, sessionDate, title, perceivedState}]` |
| GET | `/api/sessions/{id}` | — | 详情；不存在 → 404 |
| GET | `/api/exercises` | `?muscleGroupId=&q=&category=&limit=` | 选择器；不给 category 时排除 stretching；limit 默认 50 封顶 200 |
| GET | `/api/exercises/{id}/last-performance` | — | 最近那次；**从没做过 → 204（空正文）** |
| GET | `/api/volume/weekly` | `?date=` | 固定 17 块，`status ∈ NOT_CONFIGURED/UNTRAINED/BELOW/IN_RANGE/ABOVE` |
| GET | `/api/exercises/status` · POST `…/import` · POST `…/unimport` | — | 动作库安装状态与显式装卸 |

### 饮食（计划 4a）

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| GET | `/api/foods` | `?q=&limit=` | `[{id, nameZh, nameEn, source, per100:{…}, portions:[{unitName, grams}]}]` |
| POST | `/api/meals` | `MealInput` | `{mealId, items, nutrition}`；**请求体里没有 grams** |
| GET | `/api/meals/{id}` | — | 详情（条目按 `orderIndex`、每项带 `nutrition`、顶层是合计）；不存在 → 404 |
| GET | `/api/meals` | `?date=`（省略＝今天） | 当天的餐列表；没记过 → `[]` |
| GET | `/api/nutrition/daily` | `?date=`（省略＝今天） | `{date, nutrition, meals, items}`；**空的一天全 0，不是 404** |

`MealInput`：

```json
{
  "mealDate": "2026-10-19",
  "slot": "lunch",
  "eatenAt": "2026-10-19T12:30",
  "note": "食堂",
  "items": [
    { "foodId": 1, "amount": 1,   "unitName": "碗" },
    { "foodId": 9, "amount": 150, "unitName": null }
  ]
}
```

`unitName: null` 表示 **amount 本身就是克数**。`slot ∈ breakfast/lunch/dinner/snack`。
`nutrition` 固定六个字段：`{kcal, protein, carb, fat, fiber, sodium}`（钠按**毫克**）。

## 七、已知问题与取舍（不要当成 bug 重新发现）

| 事项 | 现状/理由 |
|---|---|
| **前端不发 HTTP** | 页面源与后端随机端口不同源，会被 CORS 拦掉。所以扩展了外壳的「代发」为通用代理 `api_request`；后端**没有** CORS、CSP 仍是 `connect-src 'self'`、capabilities 未改 |
| 代理把**任何状态码都当 `Ok`** | 前端要按 400/404/204 分流。`Err` 只表示传输失败（连不上/超时/读不懂） |
| 404 的正文是 `{error}` | `ApiErrors` 收了 `ResponseStatusException`。此前是 Spring 默认的 `{"timestamp":…,"error":"Not Found",…}`，**中文 reason 根本不出现**（默认 `include-message=never`） |
| **营养只按每 100 克存** | `meal_item` 上**没有** kcal 列（故意的）；热量永远实时算，改份量/换食物后没有任何旧数字 |
| **克数由后端算** | 契约里没有 `grams`；后端用 `PortionConverter` 按 `food_portion` 算。前端只在预览时按同一公式估 |
| **grams 存未定标的值** | `calc/package-info` 约定二：定标属于显示层；先舍再累加会有方向性偏差 |
| 食物 seed **只在库为空时装一次** | 逐条 upsert 会在用户删掉某条后**重启复活**它；设计文档说食物库「直接改数据即可」 |
| 食物 seed 的数值是**近似值** | 中国食物成分表转录版有版权、不可分发；`source` 一律 `manual`，有测试挡住 `cn-food-table` |
| 周容量只算 `completed=1` | 没打勾的组是「还没做/没记」，不是训练量 |
| 「没吃/没记/没做过」都不是错误 | 空的一天 → 200 + 全 0；空列表 → `[]`；没做过的动作 → 204。用 404 表达这些会让刚启用的人以为程序坏了 |
| **训练与餐都没有修改/删除端点** | 第一阶段只做「一次写完」；设计的安全线是只增改不删 |
| 动作库启动策略 | 只装一次；`unimport` 之后重启不会复活；`POST /import` 才装回来 |
| `ALLOWED_TABLES` 已含饮食四表 | 不需要改；本轮的写路径用 `origin='user'` |
| 计划编号的一个坑 | 前端的工作**按主题命名、不占编号**（同「Tauri 外壳与 Vue 前端脚手架」）。`ae8276f` 的提交信息里写成了「计划 4」，那是历史，文件已改名 |

## 八、验证纪律（这个项目的核心资产，继续沿用）

1. **测试的失效形态**：A 静默失效 / B 半途而废的闭环 / C 同义反复的断言 / D 写了≠生效 / E 死代码冒充保护 / F 无上界溢出 / G 共享可变状态 / H 计划自己的重述失真 / I 测试全绿但代码坏了。
   - 本轮又撞了几次 **H**：计划里把 `abdominals` 写成 0 组（实际 1.0，因为它是地板卧推的次要肌群）、计划说 404 的正文会有中文 reason（实际没有）。
   - 也撞了一次 **E**：`parse_api_response` 里「先判 204」那段是死代码——没有它 204 也一样得到空 body。已改成「不做正文校验」并补了一条非 204 空正文的测试。
2. **变异测试是标准动作**：新加的守卫要「改坏 → 确认变红 → 还原」。**但变异不红不等于守卫在起作用**——也可能是「那件事本来就成立」（本轮 `FAIL_ON_UNKNOWN_PROPERTIES` 就是后者）。两种要分清。

## 十一、给接手者的三条建议

1. **先看真实文件，再看计划。** 本轮计划自己失真了至少两次（0 组肌群的样本、404 的正文形状）。凡计划里写了某个 API/DTO/字段/行为，打开磁盘或跑一次再动手。
2. **「变异不红」有两种解释。** 一种是你把守卫删对了、测试没覆盖；另一种是那件事本来就成立（默认值、数据库约束、别人的校验）。分不清就会得出相反结论——本轮 `FAIL_ON_UNKNOWN_PROPERTIES` 属于后者。
3. **空、没做、没记，都是正常状态。** 空的一天是 0 千卡、没做过的动作是 204、还没记的一餐是 `[]`。把它们做成 404/500，会让第一次打开界面的人以为程序坏了——而这类错误在测试里（如果你 mock 了网络）完全看不见。
