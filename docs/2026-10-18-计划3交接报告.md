## 三、⚠️ 工具陷阱（今天新增的，每条都实际踩过）

### 1. PowerShell 的 `*>` 重定向写的是 UTF-16LE（不是 UTF-8）

用 Python 读 `java -jar ... *> boot.log` 产生的日志时，必须：

```python
raw = path.read_bytes()
text = raw.decode("utf-16") if raw[:2] in (b"\xff\xfe", b"\xfe\xff") else raw.decode("utf-8")
```

否则 `CHANGE_PORT=` 永远匹配不到（今天在 e2e 脚本里踩过一次，`port=None`）。

### 2. `mvn clean test` 会删掉 `target/`，**包括已打好的 jar**

跑完测试再 `java -jar` 会报 `Unable to access jarfile`（今天踩过）。
顺序永远是：`mvn clean test` → `mvn -B -q -DskipTests package` → `java -jar`。

### 3. `ChangeLogService` 的 `ObjectMapper` **没有注册 `JavaTimeModule`**

往 `after`/`before` 快照里放 `LocalDate` / `LocalDateTime` 会在**序列化时**抛异常，而这一步发生在
「记日志」里——它会把一次正常的写入整个弄失败。**日期/时间戳一律 `.toString()` 成字符串**
（列本来就是 TEXT，回退时 `UPDATE ... SET session_date = ?` 绑字符串完全正确）；**布尔一律 0/1 整数**。
计划 3 Task 2 有一条测试专门钉这个（`the_snapshot_stores_the_date_as_a_string_not_a_java_time_object`）。

### 4. `session_exercise.exercise_id` 是**裸外键**（没有 `ON DELETE CASCADE`）

测试里「先删动作」会直接撞 FK。清理顺序必须是：
`workout_set` → `session_exercise` → `workout_session` → `exercise`。
今天两个独立库文件的控制器测试都在 `@BeforeEach` 里按这个顺序清。

### 5. `ChangeLogJoinTableTest` **不是 `@Transactional`**（它要观察真实提交）

它会往共享库留下 `origin='user'` 的日志。**断言不要用全局 `COUNT(*) WHERE origin='user'`**，
要按「本次写入的 target_id」收口（计划 3 的 `WorkoutServiceTest` 就是这么写的）。

### 6. jsdom 环境下 Vite 会把 `node:fs` / `node:url` / `node:path` externalize 成空壳

症状：`TypeError: fileURLToPath is not a function`（今天 `theme.spec.ts` 就红在这里）。
只读文件、不碰 DOM 的 spec 在文件第一行加 `// @vitest-environment node`。已修（`dca53d8`）。

### 7. 继承自上一轮、仍然有效

- **绝不用 PowerShell 做文本往返**（`Get-Content`/`Set-Content` 默认 ANSI，会毁 UTF-8）。
- **绝不用 `java -cp target/classes` 探行为**（会读到陈旧 class）。
- **变异测试的还原用字节级备份**（`read_bytes`/`write_bytes` + sha256），不要 `git checkout --`。
- **变异脚本的 `.bak` 不要留在源码树里**（今天删过一次 `ExerciseImportService.java.bak`）。
- PowerShell 里 `git rev-parse foo^{commit}` 的 `^{...}` 会被吃掉；中文提交信息用 `git commit -F <文件>`（文件经 Python 写 UTF-8/LF）。

上一轮为了让状态栏能读 `/api/health`，做法是**由 Rust 外壳代发那一条请求**（`frontend/src-tauri` 里的命令），CSP 收紧为 `connect-src 'self'`。**前端计划必须决定训练 API 怎么走**，三选一：

1. **扩展现有的 Rust 代发命令**成一个通用代理（`GET/POST` + 路径 + body），前端只调 `invoke`。与既有做法一致，不加 CORS。
2. 后端加一份**只允许本机两个源的 CORS 白名单**。改动小，但把「任何页面都能读本机服务」的口子开大了一点。
3. Tauri 的 HTTP 插件 + capability 白名单。

**推荐 1**（不改后端暴露面，和 Task 8 的决定一致）。这一条应在**前端计划的第一节**就定下来，否则实现到一半会卡住。

## 七、已知问题与取舍（不要当成 bug 重新发现）

| 事项 | 现状/理由 |
|---|---|
| 动作库启动策略 | **只装一次**；`unimport()` 之后重启不会复活；`POST /import` 才能装回来（会连中文名一起写） |

| 训练写入的审计 | 三层**每一行**都记 `change_log`（`origin='user'`）；父行+子行都记，逆序 undo 才回得干净 |
| 训练没有修改/删除端点 | 第一阶段只做「一次写完」；智能体的安全线是只增改不删 |
