# 发布一个版本（自动更新是怎么转起来的）

> 2026-10-22 建立。**这份流程没有在真机上完整走过一遍** —— 缺的是你的 GitHub 凭据。
> 每一步都写成了可照抄的命令，走不通的地方在文末列着。

---

## 一、原理

```
你（开发者）                    GitHub Releases              用户的应用
     │                                │                        │
     │ tauri build（私钥签名）         │                        │
     ├──► latest.json + *.nsis.zip ──► │                        │
     │    + *.sig                      │                        │
     │                                │  「检查更新」            │
     │                                │◄───────────────────────┤ GET latest.json
     │                                │                        │
     │                                │  版本比本地高？          │
     │                                │───────────────────────►│ 下载 .nsis.zip
     │                                │                        │ 用公钥验签
     │                                │                        │ 静默安装
     │                                │                        │ 重启
```

三样东西各在哪：

| 东西 | 位置 | 是不是秘密 |
|---|---|---|
| **公钥** | `tauri.conf.json` 的 `plugins.updater.pubkey` | 不是（公开的，只验签） |
| **私钥** | `keys/changE-updater.key` | **是**。泄露 = 谁都能发「官方更新」 |
| **清单地址** | `tauri.conf.json` 的 `plugins.updater.endpoints` | 不是 |

当前的地址是：
`https://github.com/alpaca-cn/alpaca/releases/latest/download/latest.json`

`latest` 是 GitHub 的「指向最新 release」的固定别名，所以这个 URL 永远有效。

## 二、第一次发布要做的准备

```powershell
# 1. 装 GitHub CLI（发布用；不装也能在网页上手动上传，只是麻烦）
winget install GitHub.cli

# 2. 登录
gh auth login

# 3. 把仓库配上远端（本地目前没有 remote）
git remote add origin https://github.com/alpaca-cn/alpaca.git
git push -u origin main
```

然后把**私钥内容**存成仓库的 Actions secret（如果用 CI 发布）：

```powershell
gh secret set TAURI_SIGNING_PRIVATE_KEY --repo alpaca-cn/alpaca `
  --body (Get-Content keys/changE-updater.key -Raw)
```

> `keys/changE-updater.key` 已被 `.gitignore` 忽略，**不要**把它提交上去。

## 三、发布一个新版本

### 3.1 改版本号（两处必须一致）

```powershell
# frontend/package.json          "version": "0.2.0"
# frontend/src-tauri/tauri.conf.json  "version": "0.2.0"
```

**版本必须比用户手上那个高**，否则更新器认为「已是最新」。
`0.2.0 → 0.2.1` 可以，`0.2.0 → 0.1.9` 不行。

### 3.2 打包（签名由私钥自动完成）

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content keys/changE-updater.key -Raw
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""

cd backend
mvn -B -q -DskipTests package
Copy-Item target/change-backend-*.jar ../frontend/src-tauri/resources/change-backend.jar -Force

cd ../frontend
pnpm tauri build
```

产物在 `frontend/src-tauri/target/release/bundle/nsis/`：

```
changE_0.2.0_x64-setup.exe       ← 安装包（新用户装它，更新器也下载它）
changE_0.2.0_x64-setup.exe.sig   ← 它的签名
```

> **2026-10-22 实测修正**：我一开始以为 NSIS 会另出一个 `.nsis.zip` 给更新器用。
> 实际不会 —— NSIS 的更新产物**就是 `-setup.exe` 本身**（它支持 `/S` 静默安装），
> 签名对应那个 exe。上面这两个文件就是全部。

### 3.3 写 latest.json

```powershell
$ver = "0.2.0"
$dir = "frontend/src-tauri/target/release/bundle/nsis"
$sig = Get-Content "$dir/changE_${ver}_x64-setup.exe.sig" -Raw
$json = @{
  version = $ver
  notes   = "这一版改了什么"
  pub_date = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
  platforms = @{
    "windows-x86_64" = @{
      signature = $sig.Trim()
      url = "https://github.com/alpaca-cn/alpaca/releases/download/v$ver/changE_${ver}_x64-setup.exe"
    }
  }
} | ConvertTo-Json -Depth 5
Set-Content "$dir/latest.json" $json -Encoding UTF8
```

### 3.4 发 release

```powershell
gh release create "v0.2.0" `
  "$dir/changE_0.2.0_x64-setup.exe" `
  "$dir/changE_0.2.0_x64-setup.exe.sig" `
  "$dir/latest.json" `
  --repo alpaca-cn/alpaca `
  --title "changE v0.2.0" `
  --notes "这一版改了什么"
```

发完，用户点「检查更新 → 下载并安装 → 重启」就能升上去。

## 四、这一轮没法验证的部分

| 环节 | 状态 |
|---|---|
| 插件编译、应用启动 | **验过**（cargo check 通过） |
| 签名产物真的生成 | **验过**（`changE_0.2.0_x64-setup.exe.sig` 已在构建输出里） |
| 签名密钥生成 | **验过**（`keys/` 里有密钥对） |
| 配置正确（地址、公钥） | **没验**——要有一个真 release 才能测 |
| 下载 + 验签 + 安装 + 重启 | **没验**——同上 |
| `gh` 发布命令 | **没验**——本机没装 `gh`，也没配 remote |

**所以第一次发布请你盯着**：发完 release 之后，在旧版应用里点一次「检查更新」。
如果报错，把错误原文发我 —— `check()` 抛出的字符串通常直接说明是哪一环
（404 / 签名不匹配 / JSON 字段缺）。

## 五、常见失败

| 现象 | 原因 |
|---|---|
| 「检查失败：404」 | release 里没有 `latest.json`，或者 tag 不是 `latest` |
| 「签名不匹配」 | `latest.json` 里的 `signature` 与 `.sig` 文件内容不一致（多空格/换行） |
| 「已是最新」但明明发了新版 | 版本号没升，或者升的方向不对 |
| 下载卡在 0% | `url` 指向的资产不存在（注意要有 `_x64-setup.exe` 这个完整名字） |
